OpenCompass 深度调研：测什么、2025–2026 新增了什么、什么场景该用它

2026-11-25 · 阅读约 40 分钟 · 标签：大模型评测 OpenCompass Agent 评测 开源工具
一句话结论 OpenCompass（司南）是上海人工智能实验室推出的一站式开源大模型评测平台，也是国内覆盖最广、榜单影响力最大的评测体系。2026 年它已从"文本题库跑分工具"演进为"文本主仓 + VLMEvalKit 多模态 + AgentCompass 智能体"三件套：主仓配置目录实测 250+ 数据集，多模态支持图文/视频/音频 70+ 基准，智能体子系统覆盖 SWE-bench、Terminal-Bench、BrowseComp 等 40+ 真实任务基准。本文基于 2026-11-25 对官方 GitHub、文档与榜单的实测抓取，梳理测评维度、近期新增、适用场景与局限。

一、它是什么：基本盘与关键数字

OpenCompass 提供从数据集/模型配置、推理、评测到结果汇总的完整工作流：本地开源模型与 API 模型都支持，HuggingFace、LMDeploy、vLLM 三种推理后端可选，评测方式覆盖零样本、少样本、思维链、规则匹配与 LLM-as-Judge。Apache-2.0 许可，一条 pip install -U opencompass 即可安装。

三个站点的分工要先分清：CompassKit 是工具链（OpenCompass 主仓 + VLMEvalKit + code-evaluator 沙箱等）；CompassHub 是基准导航与投稿社区（不是数据集交易市场）；CompassRank 是榜单平台。这一"铁三角"在 2024-01 的 OpenCompass 2.0 发布时确立。

二、怎么跑：配置驱动的评测流水线

OpenCompass 的核心是一条 Python 配置驱动的离线流水线，理解配置命名规则就理解了大半个框架：

  1. 模型配置（configs/models/）：开源权重模型按 HF/LMDeploy/vLLM 后端区分；API 模型按厂商区分。文件名编码评测方式——如 gen 表示生成式、ppl 表示困惑度判别式，外加 few-shot 数与配置哈希。
  2. 数据集配置：每个数据集配置包含 reader_cfg（数据读取）、infer_cfg（提示词与推理器）、eval_cfg（评测器）三段，可用 python tools/list_configs.py mmlu gsm8k 检索。
  3. 推理（Inferencer）：负责任务切分、并发与分布式执行。2026-03 新增跨任务并发推理 + 评测监听 + 心跳机制，推理任务完成即自动触发评测。
  4. 评测（Evaluator）：规则精确匹配、数学等价判定、通用 LLM Judge、多评估器级联（CascadeEvaluator）。
  5. 结果汇总：CSV/HTML 报告，按能力维度聚合。

评测范式上，客观题走判别式（PPL/LogProb 选择题）或生成式（自由生成 + 答案抽取）；主观题走模型 pairwise 对战、LLM Judge 加人工抽检。数据污染检查在 2.0 起内置（configs 下有独立 contamination 目录与 gsm8k_contamination 配置）。

三、覆盖的测评维度：九大能力族 + 250+ 数据集

官方口径的能力维度从 1.0 时期的"知识/语言/理解/推理/考试"5 维，演进到 2026 年 README 的知识、推理、代码、科学、语言、长上下文、安全七维；实际配置目录还要加上智能体/多轮与多模态两大族。以下按主仓 configs/datasets 目录实测归类（目录名为原样名，均为 A 级证据）。

3.1 知识与综合考试

国际通用：MMLU 全家桶（mmlu、mmlu_pro、mmmlu 多语种）、GPQA、SuperGPQA（2025-03 接入，官方称覆盖 285 个研究生学科）、BBH/BBeH、ARC、HellaSwag、Winogrande、PIQA、SIQA、CommonsenseQA、NQ/TriviaQA/DROP/RACE、SimpleQA 与 chinese_simpleqa。中文考试：C-Eval、CMMLU、AGIEval、GaokaoBench、高考数学、獬豸（xiezhi）、kaoshi，以及 CLUE/FewCLUE/SuperGLUE 全家桶、LogiQA、XCOPA。

3.2 数学与推理

经典：GSM8K、GSM-Hard、MATH、SVAMP、MGSM、Game24。竞赛与高难方向在 2025–2026 明显加密：AIME 2024/2025/2026、HMMT 2026、BeyondAIME、OlymMATH、OlympiadBench、ZebraLogic、KOR-Bench、NPHardEval，以及过程评测 ProcessBench、LiveMathBench、Math401、TheoremQA 等。2025-02 专门新增 MATHVerifyEvaluator 做数学答案的符号等价判定，避免"答案等价但字符串不同"的误判。

3.3 代码

HumanEval 全系（含 CN/Multi/HumanEvalX/Plus/Pro）、MBPP 全系、BigCodeBench、LiveCodeBench（含 Pro）、MultiPL-E、DS-1000（数据科学代码）、APPS、TACO、SciCode、OJBench、LCBench。注意：主仓没有 SWE-bench 目录——智能体式软件工程任务已全部收敛到独立的 AgentCompass（见 3.8）。代码执行由配套的 code-evaluator 提供 Docker 化多语言沙箱。

3.4 长上下文

LongBench、LongBench v2、∞Bench（infinitebench）、RULER、NeedleBench v1/v2（多针大海捞针）、BABILong、LEval、LVEval、QuALITY、SumScreen、QasperCut 等，覆盖检索、多文档问答、长文摘要与长代码场景。

3.5 科学与垂直行业

  • 科学：SciBench、ScienceQA、SciEval、SciReasoner（2025-12 接入）、Intern-S1/S1-Pro 科学基准（2025-07/2026-02）、LiveSTEMBench、物理（PHYBench、CMPhysBench）、化学（ChemBench）、地球科学、海事、气候、材料、蛋白质等专业集；
  • 医学：MedBench、MedQA、MedMCQA、PubMedQA、MedCalc、MedXpertQA、NEJM AI Benchmark、HealthBench、临床显微镜 MicroVQA 等；
  • 金融：BuySideFinBench、FinanceIQ、OpenFinData，以及独立子站 CNFinBench（5 个公开 + 11 个自建数据集约 5.4 万条，含金融 Agent 四大维度 12 项长程任务，ACL Anthology 2026 收录）；
  • 法律：LawBench（与南京大学共建，记忆/理解/应用三维 20 任务）、PromptCBLUE；另有政务、土木、学术审稿（RebuttalBench）等行业集。

3.6 安全、对齐与可信

安全合集 safety、中文价值观 CValues、RealToxicityPrompts、多语种 Jigsaw/CivilComments、偏见 CrowS-Pairs（含中文版）、TruthfulQA、对抗 AdvGLUE 与 PromptBench、伪对齐 fake_alignment、幻觉 chhallu 等——覆盖毒性、偏见、幻觉、对抗鲁棒性、价值观对齐五条线。

3.7 多轮指令与工具调用

主仓内含 T-Eval（工具调用分步评测，ACL 2024）、IFEval、IFBench、InverseIFEval、advancedIF，以及 2026-07 新接入的 Multi-IF 多轮指令遵循（GenInferencer 同步支持多轮推理）。

3.8 多模态：VLMEvalKit 子系统

多模态评测由同生态的 VLMEvalKit 承担（arXiv:2407.11691，ACM MM 2024），2026-08-25 起集成进主仓统一流程。官方口径支持 70+ 图文/视频基准、200+ 模型，包括 MMBench、MMMU/MMMU-Pro、MathVista、OCRBench、ChartQA、SEED-Bench、Video-MME（2026-04 已支持 v2）、OmniDocBench、QBench-Video 等。方法论上全部 generation-based（不打 logprob），同时给精确匹配与 LLM 抽取两套分；官方明确不保证复现第三方论文的 PPL 原始分。2026-11-10 新增音频模态（首个基准 MMSU），从"视觉语言工具包"实质走向全模态。

3.9 智能体：AgentCompass 子系统（2026 年最重要新增）

2026-09-30 发布（PyPI v1.0.0，EMNLP 2026 Demo，arXiv:2607.13705）。核心设计是把 Model / Benchmark / Harness / Environment 四者解耦，支持本地进程、Docker、Daytona、Modal 等隔离执行，提供断点续跑、失败重试和完整轨迹记录（工具调用、token、延迟全留痕）。官方口径 40+ 公开基准、10+ Harness，覆盖：

任务族代表基准
软件工程SWE-bench Verified / Pro / Multilingual / SWE Atlas，以及团队自研 SWE-Bench Pro Verified（2026-09，arXiv:2609.08149，专治 reward hacking 与任务质量）
终端/计算机使用Terminal-Bench 2/2.1/4/Science、OSWorld、AndroidWorld、ScreenSpot、CyberGym
浏览/深度研究BrowseComp（含中文版）、GAIA、HLE/HLE-Verified、DeepResearch Bench、DeepSearchQA

Harness 侧已适配 Claude Code、Codex、OpenHands、OpenClaw、mini-SWE-agent 等主流智能体运行时，裁判同时支持普通 LLM Judge 与 Agentic Judge，并在跑前对模型做多模态探针（防止"看不到图/听不到音频"的模型污染结果）。

四、榜单体系：CompassRank 怎么组织

CompassRank 的榜单分三层：

  1. 官方自建榜：大语言模型客观榜、多模态客观榜、模型对战主观榜、月度榜（区分开源/闭源、标注排名升降）；
  2. 特色能力榜：MMBench 细粒度视觉、OpenVLM 视频榜、主观创作榜、VBench/VBench2.0 视频生成质量榜；
  3. 社区共建榜：11 个垂直行业榜——法律 LawBench（南大）、安全 SecBench（腾讯/清华）、金融 CFBenchmark（同济/东方财富）、价值对齐 Flames（复旦）、翻译 TransBench（阿里国际/北语）、土木 Civil-Bench（同济）、生命健康 LifeOmni（交医）、数据分析 AIDABench（商汤）、视频生成 RAVEN-Eval（央视超高清国重/中国美院/芒果 TV）等，另有独立运行的 CNFinBench 金融 Agent 榜。
两条关键规则 ① 入榜需向 opencompass@pjlab.org.cn 提交模型仓库或标准 API，不接受内部迭代模型和邀请制 API；② 反刷榜借鉴高考"公布考纲不公布考题"——每期只公开上一期题目，题目动态原创更新。这也意味着月度榜分数不宜跨月直接横比（题目在换、judge 模型也在换代，例如 VLMEvalKit 已预告 2027-01 随 OpenAI 旧模型下线把默认 judge 换成 gpt-6-luna）。

六、适用场景：什么时候该选它

五类高适配场景
  1. 模型研发团队做训练后回归：配置即代码、可断点续跑、分布式，早期口径千亿参数模型全量评测小时级；2026 年并发监听适合接 CI 做版本门禁。
  2. 一套框架测"开源 + API + 文本 + 多模态"：对国产模型矩阵（Qwen/GLM/DeepSeek/Kimi/MiniMax/豆包/Intern 系）的配置覆盖是国内最全的，LiteLLM 网关又补齐了海外 API——这是相对海外框架最实际的优势。
  3. 中文与行业垂直评测：C-Eval/CMMLU/高考/CLUE 加 LawBench、CNFinBench、SecBench、医学集，行业对标不用自己攒题。
  4. 发论文 / 送榜：CompassRank 是国内事实主流送榜渠道之一，加 Meta Llama 官方文档背书，国际语境也认。
  5. 评测 2026 年的 Agent 产品：AgentCompass 的解耦架构、沙箱隔离与轨迹留痕，比自研评测脚手架成熟，尤其适合编码/终端/Deep Research 类智能体的选型对比与回归。

七、局限：什么时候它帮不了你

  1. 工程门槛中高：纯配置文件体系，依赖组合碎片化——vLLM/LMDeploy 要独立虚拟环境，flash-attn/transformers 版本随模型变，代码执行集还得退回 Python 3.10；快速跑一个标准分数，lm-evaluation-harness 一条命令更省事。
  2. 分数跨期不可直接横比：题目按年滚动、judge 模型换代，月度榜趋势要看，绝对值别跨期减。
  3. 官方自承不保证复现第三方论文原始分：generation 与 PPL 范式差异、模型专属模板缺失都会带来偏差。
  4. "高分低能"是公开静态基准的通病：滚动原创题、HLE、AgentCompass 能缓解不能消除；榜单主干仍是选择题/静态集，真实生产效果必须用自有业务任务集补测。
  5. "一站式"是组织层面、不是单包：测 Agent 要另学 AgentCompass 一套 CLI/配置，多模态要理解 VLMEvalKit 独立版本节奏。
  6. 数据集口径混乱：README 写 100+，配置目录实测 250+（含多配置/废弃集），引用时注明口径；open issues 约 330 个，长尾问题需自行消化。
  7. 企业版/私有化没有公开报价口径：仅有火山引擎商城 SaaS 商品页（C 级线索），官方功能边界与 SLA 未公开。

九、对质量工程团队的落地建议

  1. 把它当回归门禁，而不是一次性跑分：选 10–20 个与业务相关的固定配置入 CI，重点看版本间分差与置信区间，而非总分排名；模型升级时跑污染检查。
  2. 公开基准 + 私有业务集双轨制：公开集用于行业对标，自建业务集（客服、文档、代码、工具调用）用 GenericLLMEvaluator + 人工标注校准，防止题库污染与"高分低能"。
  3. 推理模型评测换一套指标观：关注 ProcessBench 式过程正确性、analyze_repeat 复读检测、思考 token 成本与延迟，而不只是最终答案正确率。
  4. Agent 评测先建环境隔离再谈分数：直接采用 AgentCompass 的沙箱与轨迹留痕，内部评测要记录工具调用成功率、人工接管率、任务成本，参照前文具身智能质量保障一文提出的"成功率不是安全率"原则。
  5. 送榜与自研分开：送 CompassRank 解决市场背书，内部选型必须用同一版本模型、同一 judge、同一提示模板自测，并记录 judge 模型版本以保证可追溯。
